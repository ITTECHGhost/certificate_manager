# The Cerebrum

## Architectural Rules
- Always use the predefined UI themes and color palettes defined in `config.py`.
- Keep database interaction logic within `db.py`, `sync_engine.py`, or `data/repositories.py`. Never scatter raw SQL in UI files.
- UI components should use `customtkinter` (CTk) classes where possible to maintain the modern appearance.
- Follow the established standard for creating screens (using the `SidePanel` and `RecordList` patterns as seen in other screens).
- Ensure new data models and tables are correctly versioned/migrated if the schema changes.
- **Offline Sync Engine (`sync_engine.py`)**: All offline infrastructure lives here. Network status is a cached module-level flag (`_is_online`) with `is_online()`/`set_online()` accessors. The expensive `check_network_status()` pinger runs every 8s in `main.py`'s `_poll_network()`.
- **Dual-cache architecture**: (1) `read_cache` table stores SP results as JSON blobs keyed by `sha256(proc_name:args)` — transparent, works for any SP. (2) Replica tables (`students`, `personnel`, `courses`, etc.) are full table mirrors populated by `pull_mysql_to_sqlite()` — supports direct SQL queries offline.
- **Repository routing pattern**: `BaseRepository._call_read_all/one/multi` handle online→cache→return automatically. For raw-SQL reads in subclasses, use `sqlite_read_all()`/`sqlite_read_one()` behind `if not is_online()` guards. Writes go through `_call_write` (raises `OfflineModeError` offline) or `log_offline_insert()` for INSERT.
- **Temp IDs**: Offline INSERTs get monotonically decreasing negative IDs (−1, −2, ...) from `generate_temp_id()`. These are resolved to real MySQL IDs by `sync_offline_queue_to_mysql()` with FK cascading.
- **App startup is fault-tolerant**: `init_db()` in `main.py` is wrapped in try/except. If MySQL is down, the app starts in offline mode using the SQLite replica.
- **Backend Service Updates**: When updating backend files (`main.py`, `db.py`, `config.py`), make sure to copy them to the deployed service directory at `C:\AppServ\www\certificate_manager_api\`. After deploying, use `stop_service.bat` and `start_service.bat` in that folder (or in the workspace root) as Administrator to cleanly restart the registered Windows Service and apply the changes. Alternatively, `stop_server.bat` and `start_server.bat` can be used to run the server in the foreground for interactive development.

## Bug Ledger
- **ImportError: `backup_db`/`restore_db` missing from `db.py`** (2026-05-12): After the MySQL migration, `backup_db` and `restore_db` were removed from `db.py` but `settings_screen.py` still imported them, crashing on startup. Fixed by re-implementing both functions in `db.py` using `subprocess` to call the `mysqldump` and `mysql` CLI tools. Credentials are passed via the `MYSQL_PWD` environment variable (never on the command line). If the tools are not on PATH, a descriptive `RuntimeError` is raised at call-time — the app never crashes on import. Also fixed a duplicate import block in `settings_screen.py` (the first ~9 lines were duplicated) and updated file dialogs to use `.sql` instead of the legacy `.db` SQLite extension.
- **Student search/edit broken — 6 legacy bare-function calls never migrated** (2026-05-12): `EnrollmentPanel` and `StudentsScreen._do_delete_student` still called the old `data.queries` bare functions (`get_courses_for_dept_stage`, `get_enrollments_for_period`, `insert_enrollment`, `update_enrollment`, `delete_enrollment`, `delete_student`) that no longer exist after the Repository Pattern migration. This caused NameErrors at runtime whenever a user tried to: (a) open the grades panel for a period, (b) add/edit/delete an enrollment, or (c) delete a student. Fixed by replacing all 6 calls with their correct Repository equivalents: `CourseRepository().get_by_dept_stage_system()`, `EnrollmentRepository().get_by_period()`, `.insert()`, `.update()`, `.delete()`, and `StudentRepository().delete()`.
- **Search crashes on NULL values in Student and Course screens** (2026-05-12): The search logic in `StudentsScreen` and `CoursesScreen` was directly calling `.lower()` on database fields like `full_name_en` or `dept_name_ar` without checking for `NULL` (`None` in Python). If a record had a missing field, the search would crash with an `AttributeError: 'NoneType' object has no attribute 'lower'`. Fixed by adding `(value or "")` guards to all search-related fields. Also improved `CourseRepository.get_all` to correctly aggregate shared department names using `GROUP_CONCAT` so that shared courses are searchable by department.
- **Search crash: Unknown column 's.graduation_date'** (2026-05-12): `StudentRepository.search()` selected `s.graduation_date` in its SQL, but that column does not exist on the `students` table (graduation info is stored on `graduation_orders`). Every search keystroke crashed with `mysql.connector.errors.ProgrammingError: 1054`. Fixed by removing the non-existent column from the SELECT list.
- **Schema mismatch: `passed_round`, `semester_weight`, `display_type` etc. never existed in DB** (2026-05-12): Multiple repository methods and UI components referenced columns that were planned but never added to the MySQL schema. `academic_periods` has no `passed_round` column; `study_systems` has no `semester_weight`, `year_weight`, `prefix`, `display_type`, `weight_type` — the real columns are `period_display` and `calculation_weights`. Fixed `AcademicPeriodRepository` (get_by_student, insert, update), `StudySystemRepository` (get_all, get_active, insert, update), `CertificateRepository.get_full_certificate_data`, `settings_screen.py` (UI and save logic), and `students_screen.py` (period card display).
- **`course_departments` table missing from MySQL database** (2026-05-17): When opening a student's course enrollment picker, the application crashed with a `ProgrammingError: 1146` because the shared courses junction table `course_departments` was missing from the local MySQL database. Fixed by updating `init_db()` in `db.py` to dynamically verify and execute the table creation script on startup, providing a robust, self-healing database initialization.
- **Student edit crashes & missing graduation orders in MySQL database** (2026-05-17): Student updates and forms crashed due to missing columns (`graduation_date`, `graduation_semester`, `postgraduation_no`) in the local MySQL `students` table, a `KeyError: 'admission_year'` crash occurred on opening student editing because the local MySQL `graduation_orders` table was missing columns (`admission_year`, `study_type`, `notes`), and `DepartmentRepository` queries failed due to `college_ar`/`college_en` columns not existing in the `departments` table. Fixed by: (a) adding self-healing startup migrations in `db.py` (`init_db`) to automatically alter both `students` and `graduation_orders` tables with missing columns, (b) refactoring `DepartmentRepository` to join `university_settings`, (c) updating `StudentRepository.get_by_id` to join `graduation_orders` to fetch the linked `order_number` and coalesced date/semester, and (d) adding beautifully balanced fields (Graduation Order, Sequence Number, and Postgraduation No.) to the student detail card in `students_screen.py`.
- **Student academic data not loading — schema mismatches + migration targeting SQLite instead of MySQL** (2026-06-02): Clicking a student detail card crashed silently with `ProgrammingError: 1054 Unknown column 'study_system_id'` (and `'is_second_round'`), because the MySQL `academic_periods` and `courses` tables were missing `study_system_id` / `is_shared` columns, and the `enrollments` table uses `passed_round ENUM` while the code referenced the non-existent `is_second_round` column. Additionally, both `academic_periods` and `enrollments` had **0 rows** in MySQL because the migration tool (`tools/migrate_mysql.py`) was hardcoded to write to SQLite via `sqlite3.connect()`. Fixed by: (a) adding self-healing column migrations in `db.py` `init_db()` for `academic_periods.study_system_id`, `courses.study_system_id`, and `courses.is_shared`; (b) rewriting `EnrollmentRepository` (get_by_period, insert, update) and `CertificateRepository.get_full_certificate_data` in `data/repositories.py` to use `e.passed_round` with a `CASE` alias for backward-compatible `is_second_round` dict keys; (c) fully refactoring `tools/migrate_mysql.py` to use `db.get_connection()` (MySQL) instead of `sqlite3.connect()`, converting all `?` placeholders to `%s`, `INSERT OR IGNORE` to `INSERT IGNORE`, removing PRAGMA/executescript, fixing column names (`password_hash`/`personnel_role` for personnel, `passed_round` for enrollments), and using a buffered cursor to prevent `Unread result found` errors.
- **Certificate Nationality showing as 'None' and Top Average formatting as long unrounded float** (2026-06-02): When generating certificates, the student's nationality appeared as 'None' because the migration tool hardcoded a default `nationality_id` of `111` for unmapped countries, but country `111` did not exist in the new `countries` table (Iraq is actually `274`). This caused the `LEFT JOIN countries` query to return `None`. Additionally, the 'First Student Average' was inserted into the UI without rounding, displaying an incredibly long 15-decimal float (e.g., 66.89600372314453). Fixed by: (a) running a database UPDATE to set all `nationality_id = 111` to `274`; (b) changing the fallback country mapping in `tools/migrate_mysql.py` to `274`; and (c) modifying `certificate_screen.py` to intercept `data.get("top_average")` and round it to 3 decimal places using `round(float(top_avg), 3)` before inserting it into the UI.
- **Missing periods/courses in Certificate generation for Semester and Annual systems** (2026-06-02): Certificates were missing courses because the period pairing loop in `certificate_screen.py` had a hardcoded `half = 1` condition, causing it to only ever process the first two periods (ignoring the rest of the student's academic history). Additionally, Semester-based students didn't have their labels correctly formatted (missing "First/Second Semester" and the academic year span). Fixed by separating the generation logic: (a) for `is_annual`, restored the dynamic vertical pairing `half = (num_periods + 1) // 2` to pair Year 1/Year 3 and Year 2/Year 4; (b) for Semester systems, implemented a chunk-by-2 sequential pairing that places Semester 1 on the right and Semester 2 on the left, while correctly assigning the overarching Academic Year to `row_year_display` to span the table.
- **Offline mode empty screens & Students screen direct DB call crashes** (2026-06-17): Offline browsing displayed empty screens for academic periods, enrollments, and courses due to missing SQLite replica query routing fallbacks, and the database replication snapshot failed because the SQLite replica `academic_periods` table was missing the `semester_num` column (which exists in MySQL). Furthermore, adding academic periods and loading course pickers on the Students Screen crashed/hung when offline due to direct raw SQL execution and manual `get_connection()` calls in `students_screen.py`. Fixed by: (a) adding `semester_num` to the SQLite `academic_periods` replica table and running a self-healing `ALTER TABLE` schema migration on startup; (b) implementing proper SQLite UNION/join query fallbacks in `AcademicPeriodRepository.get_by_student`, `EnrollmentRepository.get_by_period`, `CourseRepository.get_all`, and `CourseRepository.get_by_department`; and (c) refactoring the Students Screen's `_add_period` and `_reload_course_picker` methods to call the clean repository interface (`AcademicPeriodRepository.insert` and `CourseRepository.get_by_dept_stage_system`), resolving offline freezes and ensuring full offline data visibility.
- **Departments Screen KeyError & Inbound Sync Engine robustification** (2026-06-17): The Departments screen crashed with a KeyError on `college_ar` when online because the MySQL stored procedure `GetAllDepartments` outputs `college_name_ar` and `college_name_en` while the offline repository route outputs aliased `college_ar` and `college_en` columns. Fixed by (a) refactoring the UI to safely use `.get()` with fallbacks, (b) updating the offline query aliases in `DepartmentRepository` to return both formats, and (c) updating the inbound sync engine snapshot function `download_mysql_snapshot` to dynamically drop/recreate local tables matching the MySQL schema using text columns, including table mapping from `settings` to `university_settings`.
- **SQLite Grade Mismatch TypeError & File-based History Log Reversion** (2026-06-17): Offline student view crashed with `TypeError: '>=' not supported between instances of 'str' and 'int'` because SQLite replica returned average values as string variables. Additionally, the audit_log table did not exist in MySQL databases. Fixed by (a) adding safe float casting inside the `get_grade` helper in `db.py`, and (b) reverting the `AuditRepository` class in `data/repositories.py` to parse from the legacy file-based `activity_log.txt` log system with milliseconds removed from timestamps for visual clarity.
- **Relational Data Disconnect due to SQLite Type Coercion** (2026-06-17): Offline mode displayed empty screens for student academic periods and course enrollments because the snapshot engine `download_mysql_snapshot` strictly defined all columns as `TEXT` in the SQLite replica tables and forced string casting (`str(val)`) on all cell values. This coerced integer IDs and Foreign Keys into strings (e.g. `student_id = "4"`), causing the repository queries using numeric matching (`WHERE student_id = ?` with parameter `4`) to return empty lists. Fixed by (a) implementing a type-preserving `safe_cast(val)` helper that preserves `int`/`float` values, and (b) omitting strict `TEXT` data typing from dynamic `CREATE TABLE` queries, letting SQLite's dynamic typing naturally assign numeric types.
- **SQLite Performance Sluggishness & Arabic Byte Decoding Mismatch** (2026-06-17): Offline browsing was extremely slow, freezing the UI on larger datasets due to full-table scans. Additionally, student nationality and birthplace Arabic strings returned empty/corrupted results because VARCHAR/TEXT columns from MySQL were fetched as raw bytearray/bytes payloads. Fixed by (a) dynamically injecting `INTEGER PRIMARY KEY` for `id` columns in SQLite replica schemas, (b) automatically executing `CREATE INDEX` on all foreign key columns ending with `_id` to speed up join/filter queries, and (c) decoding `bytes`/`bytearray` objects using `utf-8` in the snapshot casting helper to display correct Arabic strings.
- **Missing postgraduation number UI / Repository syntax error / Startup sync robustification** (2026-06-17): The Students Screen displayed `None` for student postgraduation numbers because the legacy MySQL Stored Procedures omit `postgraduation_number` from their SELECT outputs, and the UI logic was missing type-safe guard fallbacks. Furthermore, an incomplete repository merge introduced Python syntax parsing errors. Fixed by: (a) fixing the syntax errors in `data/repositories.py` and implementing a supplemental `_inject_missing_graduation_numbers` query routing through `is_online()`; (b) modifying `db.py` on startup to unconditionally copy legacy `postgraduation_number` values to the `postgraduation_no` column where NULL; and (c) refactoring `screens/students_screen.py` to intercept and clean both sequence and postgraduation numbers using visual fallbacks (`—`) instead of printing "None".
- **Missing active user name and role in top header bar** (2026-06-18): The top header bar failed to display the active logged-in user's name and role after successful authentication. Fixed by adding a dedicated `CTkLabel` (user_label) in `HeaderBar` class in `main.py` positioned next to the network status indicator, implementing a `set_user` method on `HeaderBar`, and calling `self._header.set_user(user_data)` upon successful login in `CertificateManagerApp._on_login_success`.
- **Application crash after sign-in page (KeyError: 'corner_radius')** (2026-06-18): Custom theme files (`orange.json`, `purple.json`, `red.json`) lack various default keys (like `corner_radius` for `CTkLabel` under CustomTkinter v5) that standard CustomTkinter widgets expect. Calling `set_default_color_theme()` on the custom theme file path completely replaced `ThemeManager.theme` dictionary, resulting in KeyErrors when creating widgets after logging in. Fixed by refactoring `refresh_config()` in `config.py` to load CustomTkinter's default `"blue"` theme first (ensuring all standard keys exist), recursively merging the custom JSON theme over it, and applying platform-specific filtering and class name normalizing.
- **Student average validation failure, date formatting errors, and postgraduation number saving issue** (2026-07-01): The student form rejected float average values (e.g. `66.0`) because validation strictly checked `.isdigit()` and cast to `int()`. Additionally, dates entered in `YYYY/M/D` formats caused database validation errors. Finally, the postgraduation number was not saved because the client-side `StudentRepository` mapped it as `postgraduation_no` instead of `postgraduation_number` expected by the API and local database schema. Fixed by: (a) updating `SidePanel` to trigger a modal popup warning alert for all validation errors; (b) implementing a `format_to_standard_date` helper to auto-convert slash-separated dates to standard `YYYY-MM-DD` on validation; (c) validating and parsing student averages as float decimals; and (d) renaming `postgraduation_no` to `postgraduation_number` in `data/repositories.py` payload mappings and SQLite select queries.
- **Course Passed Round Dropdown and Student Study System/Type Edit Regressions** (2026-07-02): (1) Selecting non-first exam trials (Round 2 or 3) hard-saved as Round 2 because the API server mapped any truthy value (like `is_second = 1, 2, 3`) to `'2'`. Fixed by checking integer round values (`2` -> `'2'`, `3` -> `'3'`, default -> `'1'`) in both server API routes and client repositories. (2) Opening student edit profiles incorrectly reset the Study Type to "Morning" for students under study system ID 3 (Annual/Evening). Fixed by casting `study_system_id` to integer before matching database configurations in the populate view, and cleanly reconstructing the structural `study_system_id` mapping upon update saves. Also fixed the details card/certificate query: modified the database stored procedures `GetStudentDossierByID` and `GetFullCertificateData` as well as repository offline projections to correctly return `ss.study_day_type AS study_type`, and updated the UI's display logic to handle capitalization mismatch (matching both 'Morning' and 'morning'). Additionally, fixed a logical sequence bug in certificate attempt calculation where checking `is_second_round == 1` first (which is derived from `passed_round != '1'`) caused third-round attempts to be incorrectly evaluated as second-round attempts (adding 2 instead of 3). This was resolved by evaluating `pr == '3'` first. Finally, added a command wrapper to client `main.py` startup that restarts the `FastAPICertificateManager` Windows Service during development execution to guarantee code changes reload.
- **Graduation Orders screen empty due to outdated deployed service code** (2026-07-05): The FastAPI server service runs from a separate folder (`C:\AppServ\www\certificate_manager_api`) and was executing the old codebase. The old codebase did not match the updated MySQL stored procedure argument signature (expected 2 parameters `limit` and `offset` but called with 0), causing backend failures which UI repositories returned as empty results. Fixed by: (a) copying the updated `main.py`, `db.py`, and `config.py` files to the deployed service directory, and (b) instructing a service restart.
- **Student search SP schema mismatch & API search crashes** (2026-07-06): The student search Stored Procedure `SearchStudentsBasic` in MySQL was updated to return `student_id`, `name_ar`, and `name_en` columns, but queried them from `students` table where they do not exist (actual columns are `id`, `full_name_ar`, `full_name_en`), causing execution crashes. Fixed by (a) dropping and recreating `SearchStudentsBasic` in MySQL to query the correct table columns while aliasing them to `student_id`, `name_ar`, and `name_en` to preserve the new interface; (b) ensuring both `admission_year` and `graduation_year` exist in both MySQL and SQLite databases (`students`, `local_students`, and `graduation_orders` tables); (c) syncing the API `/students/search/basic` route to the workspace and deployed codebases; and (d) refactoring the client `StudentRepository.search()` method to robustly map and normalize the returned search dict keys.
