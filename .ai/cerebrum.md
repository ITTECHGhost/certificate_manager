# The Cerebrum

## Architectural Rules
- Always use the predefined UI themes and color palettes defined in `config.py`.
- Keep database interaction logic within `db.py` or use centralized queries from `data/queries.py` instead of scattering SQL throughout UI files.
- UI components should use `customtkinter` (CTk) classes where possible to maintain the modern appearance.
- Follow the established standard for creating screens (using the `SidePanel` and `RecordList` patterns as seen in other screens).
- Ensure new data models and tables are correctly versioned/migrated if the schema changes.

## Bug Ledger
- **ImportError: `backup_db`/`restore_db` missing from `db.py`** (2026-05-12): After the MySQL migration, `backup_db` and `restore_db` were removed from `db.py` but `settings_screen.py` still imported them, crashing on startup. Fixed by re-implementing both functions in `db.py` using `subprocess` to call the `mysqldump` and `mysql` CLI tools. Credentials are passed via the `MYSQL_PWD` environment variable (never on the command line). If the tools are not on PATH, a descriptive `RuntimeError` is raised at call-time — the app never crashes on import. Also fixed a duplicate import block in `settings_screen.py` (the first ~9 lines were duplicated) and updated file dialogs to use `.sql` instead of the legacy `.db` SQLite extension.
- **Student search/edit broken — 6 legacy bare-function calls never migrated** (2026-05-12): `EnrollmentPanel` and `StudentsScreen._do_delete_student` still called the old `data.queries` bare functions (`get_courses_for_dept_stage`, `get_enrollments_for_period`, `insert_enrollment`, `update_enrollment`, `delete_enrollment`, `delete_student`) that no longer exist after the Repository Pattern migration. This caused NameErrors at runtime whenever a user tried to: (a) open the grades panel for a period, (b) add/edit/delete an enrollment, or (c) delete a student. Fixed by replacing all 6 calls with their correct Repository equivalents: `CourseRepository().get_by_dept_stage_system()`, `EnrollmentRepository().get_by_period()`, `.insert()`, `.update()`, `.delete()`, and `StudentRepository().delete()`.
- **Search crashes on NULL values in Student and Course screens** (2026-05-12): The search logic in `StudentsScreen` and `CoursesScreen` was directly calling `.lower()` on database fields like `full_name_en` or `dept_name_ar` without checking for `NULL` (`None` in Python). If a record had a missing field, the search would crash with an `AttributeError: 'NoneType' object has no attribute 'lower'`. Fixed by adding `(value or "")` guards to all search-related fields. Also improved `CourseRepository.get_all` to correctly aggregate shared department names using `GROUP_CONCAT` so that shared courses are searchable by department.
- **Search crash: Unknown column 's.graduation_date'** (2026-05-12): `StudentRepository.search()` selected `s.graduation_date` in its SQL, but that column does not exist on the `students` table (graduation info is stored on `graduation_orders`). Every search keystroke crashed with `mysql.connector.errors.ProgrammingError: 1054`. Fixed by removing the non-existent column from the SELECT list.
- **Schema mismatch: `passed_round`, `semester_weight`, `display_type` etc. never existed in DB** (2026-05-12): Multiple repository methods and UI components referenced columns that were planned but never added to the MySQL schema. `academic_periods` has no `passed_round` column; `study_systems` has no `semester_weight`, `year_weight`, `prefix`, `display_type`, `weight_type` — the real columns are `period_display` and `calculation_weights`. Fixed `AcademicPeriodRepository` (get_by_student, insert, update), `StudySystemRepository` (get_all, get_active, insert, update), `CertificateRepository.get_full_certificate_data`, `settings_screen.py` (UI and save logic), and `students_screen.py` (period card display).
- **`course_departments` table missing from MySQL database** (2026-05-17): When opening a student's course enrollment picker, the application crashed with a `ProgrammingError: 1146` because the shared courses junction table `course_departments` was missing from the local MySQL database. Fixed by updating `init_db()` in `db.py` to dynamically verify and execute the table creation script on startup, providing a robust, self-healing database initialization.
- **Student edit crashes & missing graduation orders in MySQL database** (2026-05-17): Student updates and forms crashed due to missing columns (`graduation_date`, `graduation_semester`, `postgraduation_no`) in the local MySQL `students` table, a `KeyError: 'admission_year'` crash occurred on opening student editing because the local MySQL `graduation_orders` table was missing columns (`admission_year`, `study_type`, `notes`), and `DepartmentRepository` queries failed due to `college_ar`/`college_en` columns not existing in the `departments` table. Fixed by: (a) adding self-healing startup migrations in `db.py` (`init_db`) to automatically alter both `students` and `graduation_orders` tables with missing columns, (b) refactoring `DepartmentRepository` to join `university_settings`, (c) updating `StudentRepository.get_by_id` to join `graduation_orders` to fetch the linked `order_number` and coalesced date/semester, and (d) adding beautifully balanced fields (Graduation Order, Sequence Number, and Postgraduation No.) to the student detail card in `students_screen.py`.
- **Student academic data not loading — schema mismatches + migration targeting SQLite instead of MySQL** (2026-06-02): Clicking a student detail card crashed silently with `ProgrammingError: 1054 Unknown column 'study_system_id'` (and `'is_second_round'`), because the MySQL `academic_periods` and `courses` tables were missing `study_system_id` / `is_shared` columns, and the `enrollments` table uses `passed_round ENUM` while the code referenced the non-existent `is_second_round` column. Additionally, both `academic_periods` and `enrollments` had **0 rows** in MySQL because the migration tool (`tools/migrate_mysql.py`) was hardcoded to write to SQLite via `sqlite3.connect()`. Fixed by: (a) adding self-healing column migrations in `db.py` `init_db()` for `academic_periods.study_system_id`, `courses.study_system_id`, and `courses.is_shared`; (b) rewriting `EnrollmentRepository` (get_by_period, insert, update) and `CertificateRepository.get_full_certificate_data` in `data/repositories.py` to use `e.passed_round` with a `CASE` alias for backward-compatible `is_second_round` dict keys; (c) fully refactoring `tools/migrate_mysql.py` to use `db.get_connection()` (MySQL) instead of `sqlite3.connect()`, converting all `?` placeholders to `%s`, `INSERT OR IGNORE` to `INSERT IGNORE`, removing PRAGMA/executescript, fixing column names (`password_hash`/`personnel_role` for personnel, `passed_round` for enrollments), and using a buffered cursor to prevent `Unread result found` errors.
- **Certificate Nationality showing as 'None' and Top Average formatting as long unrounded float** (2026-06-02): When generating certificates, the student's nationality appeared as 'None' because the migration tool hardcoded a default `nationality_id` of `111` for unmapped countries, but country `111` did not exist in the new `countries` table (Iraq is actually `274`). This caused the `LEFT JOIN countries` query to return `None`. Additionally, the 'First Student Average' was inserted into the UI without rounding, displaying an incredibly long 15-decimal float (e.g., 66.89600372314453). Fixed by: (a) running a database UPDATE to set all `nationality_id = 111` to `274`; (b) changing the fallback country mapping in `tools/migrate_mysql.py` to `274`; and (c) modifying `certificate_screen.py` to intercept `data.get("top_average")` and round it to 3 decimal places using `round(float(top_avg), 3)` before inserting it into the UI.
- **Missing periods/courses in Certificate generation for Semester and Annual systems** (2026-06-02): Certificates were missing courses because the period pairing loop in `certificate_screen.py` had a hardcoded `half = 1` condition, causing it to only ever process the first two periods (ignoring the rest of the student's academic history). Additionally, Semester-based students didn't have their labels correctly formatted (missing "First/Second Semester" and the academic year span). Fixed by separating the generation logic: (a) for `is_annual`, restored the dynamic vertical pairing `half = (num_periods + 1) // 2` to pair Year 1/Year 3 and Year 2/Year 4; (b) for Semester systems, implemented a chunk-by-2 sequential pairing that places Semester 1 on the right and Semester 2 on the left, while correctly assigning the overarching Academic Year to `row_year_display` to span the table.
