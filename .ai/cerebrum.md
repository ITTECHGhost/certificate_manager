# The Cerebrum

## Architectural Rules
- Always use the predefined UI themes and color palettes defined in `config.py`.
- Keep database interaction logic within `db.py`, `sync_engine.py`, or `data/repositories.py`. Never scatter raw SQL in UI files.
- UI components should use `customtkinter` (CTk) classes where possible to maintain the modern appearance.
- Follow the established standard for creating screens (using the `SidePanel` and `RecordList` patterns as seen in other screens).
- Ensure new data models and tables are correctly versioned/migrated if the schema changes.
- **Offline Sync Engine (`sync_engine.py`)**: All offline infrastructure lives here. Network status is a cached module-level flag (`_is_online`) with `is_online()`/`set_online()` accessors. The expensive `check_network_status()` pinger runs every 8s in `main.py`'s `_poll_network()`.
- **Dual-cache architecture**: (1) `read_cache` table stores SP results as JSON blobs keyed by `sha256(proc_name:args)` — transparent, works for any SP. (2) Replica tables (`students`, `personnel`, `courses`, etc.) are full table mirrors populated by `pull_mysql_to_sqlite()` — supports direct SQL queries offline.
- **Repository routing pattern**: `BaseRepository._call_read_all/one/multi` handle online→cache→return automatically. For raw-SQL reads in subclasses, use `sqlite_read_all()`/`sqlite_read_one()` behind `if not is_online()` guards. Writes go through `_call_write` (raises `OfflineModeError` offline) or `log_offline_insert()` for INSERT.
- **Temp IDs**: Offline INSERTs get monotonically decreasing negative IDs (−1, −2, ...) from `generate_temp_id()`. These are resolved to real MySQL IDs by `sync_offline_queue_to_mysql()` with FK cascading.
- **App startup is fault-tolerant**: `init_db()` in `main.py` is wrapped in try/except. If MySQL is down, the app starts in offline mode using the SQLite replica.
- **Backend Service Updates**: When updating backend files (`main.py`, `db.py`, `config.py`), make sure to copy them to the deployed service directory at `C:\AppServ\www\certificate_manager_api\`. After deploying, use `stop_service.bat` and `start_service.bat` in that folder (or in the workspace root) as Administrator to cleanly restart the registered Windows Service and apply the changes. Alternatively, `stop_server.bat` and `start_server.bat` can be used to run the server in the foreground for interactive development.

Also improved `CourseRepository.get_all` to correctly aggregate shared department names using `GROUP_CONCAT` so that shared courses are searchable by department.
